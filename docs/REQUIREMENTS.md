## 화면별 상세 사용 시나리오

> 아래 시나리오는 위 요구사항을 실제 화면 흐름으로 풀어쓴 MVP 기준 사용 시나리오이다.

### 1. 로그인 화면

**대상 사용자:** 수강생, 튜터/관리자  
**관련 요구사항:** REQ-002, REQ-003, REQ-004

| 단계 | 사용자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 사용자가 로그인 화면에 접속한다. | 로그인 가능한 인증 수단을 표시한다. |
| 2 | 사용자가 계정 정보를 입력하고 로그인을 요청한다. | 입력된 사용자 정보를 인증한다. |
| 3 | 인증에 성공한다. | 사용자 역할이 수강생인지 튜터/관리자인지 확인한다. |
| 4 | 수강생으로 확인된다. | 학생 홈 화면으로 이동한다. |
| 5 | 튜터/관리자로 확인된다. | 관리자 기능을 사용할 수 있도록 한다. |

**예외/제약**
- 인증되지 않은 사용자는 평가, 팀 정보, 결과 화면을 사용할 수 없다.
- 초기 MVP에서는 Django Auth를 우선 사용하고 이후 Google 로그인을 연동한다.

**완료 조건:** 인증된 사용자가 자신의 역할에 맞는 화면에 진입한다.

### 2. 학생 홈 화면

**대상 사용자:** 수강생  
**관련 요구사항:** REQ-006, REQ-011, REQ-022

| 단계 | 사용자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 수강생이 로그인한다. | 현재 진행 중인 평가 회차를 조회한다. |
| 2 | 학생 홈 화면에 진입한다. | 현재 평가 회차, 과제, 소속 팀, 평가 상태를 요약하여 표시한다. |
| 3 | 현재 팀 정보를 확인한다. | 본인이 속한 팀과 팀 정보 화면으로 이동할 수 있도록 한다. |
| 4 | 현재 과제를 확인한다. | 과제 정보 화면으로 이동할 수 있도록 한다. |
| 5 | 평가 상태를 확인한다. | 팀 평가 및 개인 평가 진행 여부를 확인할 수 있도록 한다. |
| 6 | 결과가 공개된 경우 결과를 확인한다. | 공개 설정이 허용된 결과만 결과 화면에서 확인할 수 있도록 한다. |

**예외/제약**
- 진행 중인 평가 회차가 없는 경우 평가 기능을 제공하지 않는다.
- 결과가 비공개 상태이면 결과 상세 정보를 노출하지 않는다.

**완료 조건:** 수강생이 현재 회차에서 해야 할 과제와 평가 상태를 파악할 수 있다.

### 5. 팀 평가 화면

**대상 사용자:** 수강생  
**관련 요구사항:** REQ-012, REQ-013, REQ-014, REQ-017

| 단계 | 사용자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 수강생이 팀 평가 화면에 진입한다. | 현재 평가 회차와 사용자의 소속 팀을 확인한다. |
| 2 | 평가 가능한 팀 목록을 확인한다. | 전체 팀 중 사용자의 소속 팀을 제외한 팀만 평가 대상으로 제공한다. |
| 3 | 평가할 다른 팀을 선택한다. | 해당 회차의 팀 평가 템플릿과 문항을 조회한다. |
| 4 | 각 문항에 점수를 입력한다. | 각 문항에 대해 기본 1~5점 범위의 값을 입력받는다. |
| 5 | 평가 제출을 요청한다. | 선택한 대상이 본인 팀인지 다시 확인한다. |
| 6 | 중복 평가 여부를 검사한다. | 동일 회차에서 동일 사용자가 해당 팀을 이미 평가했는지 확인한다. |
| 7 | 검증에 통과한다. | 평가 응답을 저장하고 해당 팀에 대한 평가를 완료 처리한다. |
| 8 | 다시 팀 평가 화면을 확인한다. | 완료한 팀과 아직 평가하지 않은 팀을 구분하여 확인할 수 있도록 한다. |

**예외/제약**
- 본인이 속한 팀은 평가할 수 없다.
- 동일 평가 회차에서 같은 팀을 두 번 평가할 수 없다.
- 점수는 기본적으로 각 문항당 1~5점 범위를 사용한다.
- 현재 회차에 설정된 평가 문항을 기준으로 평가한다.

**완료 조건:** 다른 팀에 대한 유효한 평가가 한 번만 저장된다.

### 6. 개인 평가 화면

**대상 사용자:** 수강생  
**관련 요구사항:** REQ-012, REQ-013, REQ-015, REQ-016, REQ-017

| 단계 | 사용자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 수강생이 개인 평가 화면에 진입한다. | 현재 평가 회차의 팀 구성 정보를 조회한다. |
| 2 | 평가 가능한 구성원을 확인한다. | 같은 팀 구성원 중 본인을 제외한 학생만 평가 대상으로 표시한다. |
| 3 | 평가할 팀원을 선택한다. | 해당 회차의 개인 평가 템플릿과 문항을 조회한다. |
| 4 | 각 문항에 점수를 입력한다. | 각 문항에 대해 기본 1~5점 범위의 값을 입력받는다. |
| 5 | 평가 제출을 요청한다. | 평가 대상이 같은 팀 구성원인지 확인한다. |
| 6 | 본인 평가 여부를 검사한다. | 평가자와 평가 대상이 동일하면 제출을 차단한다. |
| 7 | 중복 평가 여부를 검사한다. | 동일 회차에서 동일 사용자가 해당 팀원을 이미 평가했는지 확인한다. |
| 8 | 검증에 통과한다. | 개인 평가 응답을 저장하고 해당 팀원 평가를 완료 처리한다. |
| 9 | 다시 개인 평가 화면을 확인한다. | 완료한 팀원과 아직 평가하지 않은 팀원을 구분하여 확인할 수 있도록 한다. |

**예외/제약**
- 같은 팀 구성원만 개인 평가할 수 있다.
- 자기 자신은 평가할 수 없다.
- 다른 팀 학생은 평가할 수 없다.
- 동일 평가 회차에서 같은 대상을 두 번 평가할 수 없다.

**완료 조건:** 같은 팀의 다른 구성원에 대한 유효한 개인 평가가 한 번만 저장된다.

### 7. 평가 제출 현황 화면

**대상 사용자:** 수강생

| 단계 | 사용자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 수강생이 평가 제출 현황 화면에 진입한다. | 현재 평가 회차에서 평가 가능한 대상을 조회한다. |
| 2 | 팀 평가 현황을 확인한다. | 다른 팀별 평가 완료/미완료 상태를 표시한다. |
| 3 | 개인 평가 현황을 확인한다. | 같은 팀의 다른 구성원별 평가 완료/미완료 상태를 표시한다. |
| 4 | 미완료 평가를 선택한다. | 해당 팀 평가 또는 개인 평가 화면으로 이동할 수 있도록 한다. |
| 5 | 모든 필수 평가를 제출한다. | 해당 사용자의 평가가 모두 완료되었음을 확인할 수 있도록 한다. |

**예외/제약**
- 본인 팀은 팀 평가 대상 수에 포함하지 않는다.
- 본인은 개인 평가 대상 수에 포함하지 않는다.
- 저장된 평가 데이터를 기준으로 완료 여부를 판단한다.

**완료 조건:** 수강생이 본인의 평가 제출 여부를 대상별로 확인할 수 있다.

### 8. 결과 화면

**대상 사용자:** 수강생  
**관련 요구사항:** REQ-018, REQ-019, REQ-020, REQ-021, REQ-022

| 단계 | 사용자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 평가가 종료된 후 결과 화면에 진입한다. | 현재 평가 회차의 결과와 공개 설정을 조회한다. |
| 2 | 팀 결과 공개 여부를 확인한다. | 공개 설정에 따라 팀 1위 또는 허용된 팀 순위를 표시한다. |
| 3 | 개인 점수 공개 여부를 확인한다. | 공개가 허용된 경우 본인의 개인 관련 점수를 표시한다. |
| 4 | 개인 순위 공개 여부를 확인한다. | 공개가 허용된 경우 개인 순위를 표시한다. |
| 5 | 공개되지 않은 항목을 확인하려 한다. | 해당 결과는 표시하지 않는다. |

**결과 계산 기준**
- 팀 점수: 다른 학생들에게 받은 팀 평가 결과를 기반으로 계산한다.
- 개인 점수: 같은 팀 구성원에게 받은 개인 평가 결과를 기반으로 계산한다.
- 개인 최종점수: `팀 점수 × 40% + 개인 점수 × 60%`로 계산한다.
- 팀 순위는 팀 점수, 개인 순위는 개인 최종점수를 기준으로 계산한다.

**예외/제약**
- 결과 공개 여부는 평가 회차별 관리자 설정을 따른다.
- 관리자가 비공개로 설정한 점수나 순위는 수강생에게 노출하지 않는다.

**완료 조건:** 수강생은 관리자가 공개한 범위 내에서만 평가 결과를 확인할 수 있다.

### 9. 관리자 화면

**대상 사용자:** 튜터/관리자  
**관련 요구사항:** REQ-005 ~ REQ-010, REQ-012, REQ-018 ~ REQ-024

#### 9-1. 수강생 관리

| 단계 | 관리자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 수강생 관리 기능에 진입한다. | 등록된 수강생 목록을 조회한다. |
| 2 | 수강생을 등록한다. | 사용자 식별 정보와 수강생 정보를 저장한다. |
| 3 | 기존 수강생 정보를 수정한다. | 수정된 정보를 저장한다. |
| 4 | 참여 여부를 관리한다. | 활성 상태를 팀 편성 및 운영 시 활용할 수 있도록 한다. |

#### 9-2. 평가 회차 및 과제 관리

| 단계 | 관리자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 새로운 평가 회차를 생성한다. | 평가명, 과제, 기간, 팀 수 등의 회차 정보를 저장한다. |
| 2 | 평가 회차의 진행 상태를 설정한다. | 현재 회차의 상태를 저장한다. |
| 3 | 필요한 경우 회차 정보를 수정한다. | 변경된 회차 정보를 반영한다. |

#### 9-3. 팀 편성

| 단계 | 관리자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 평가 회차의 팀 수를 설정한다. | 팀 편성을 위한 기준 팀 수를 저장한다. |
| 2 | 수동 편성을 선택한다. | 관리자가 학생을 직접 팀에 배치할 수 있도록 한다. |
| 3 | 자동 편성을 선택한다. | 누적 개인점수 또는 시드를 기준으로 팀 편성을 수행한다. |
| 4 | 자동 편성 결과를 확인한다. | 팀별 인원과 성적 분포를 확인할 수 있도록 결과를 표시한다. |
| 5 | 필요한 학생을 다른 팀으로 이동한다. | 자동 편성 결과를 관리자가 수동 수정할 수 있도록 한다. |
| 6 | 팀 편성을 확정한다. | 해당 평가 회차의 최종 팀 구성을 저장한다. |

**팀 편성 제약**
- 팀별 인원 차이가 지나치게 크지 않도록 한다.
- 상위권 또는 하위권 학생이 특정 팀에 지나치게 몰리지 않도록 한다.
- 자동 편성 후에도 관리자가 수정할 수 있어야 한다.

#### 9-4. 평가 템플릿 관리

| 단계 | 관리자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 평가 템플릿을 생성한다. | 평가 회차에 사용할 템플릿을 저장한다. |
| 2 | 팀 평가 문항을 작성한다. | 팀 평가용 문항을 템플릿에 연결한다. |
| 3 | 개인 평가 문항을 작성한다. | 개인 평가용 문항을 템플릿에 연결한다. |
| 4 | 문항을 확인한다. | 각 문항이 기본 1~5점 척도로 평가될 수 있도록 한다. |

#### 9-5. 평가 시작 및 종료

| 단계 | 관리자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 팀 구성과 평가 문항을 확인한다. | 평가 진행에 필요한 회차 정보를 확인한다. |
| 2 | 평가를 시작한다. | 수강생이 팀 평가와 개인 평가를 수행할 수 있는 상태로 변경한다. |
| 3 | 평가 진행 결과를 확인한다. | 저장된 평가 결과를 조회할 수 있도록 한다. |
| 4 | 평가를 종료한다. | 해당 회차의 평가 진행을 종료 상태로 변경한다. |

#### 9-6. 점수 및 순위 계산

| 단계 | 관리자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 종료된 평가 회차의 결과 계산을 실행한다. | 각 팀이 받은 팀 평가를 집계하여 팀 점수를 계산한다. |
| 2 | 개인 평가 결과를 집계한다. | 같은 팀 구성원에게 받은 평가를 기반으로 개인 점수를 계산한다. |
| 3 | 개인 최종점수를 계산한다. | `팀 점수 40% + 개인 점수 60%` 비율을 적용한다. |
| 4 | 팀 순위를 계산한다. | 팀 점수를 기준으로 순위를 산출한다. |
| 5 | 개인 순위를 계산한다. | 개인 최종점수를 기준으로 순위를 산출한다. |
| 6 | 계산 결과를 확인한다. | 관리자는 전체 팀 및 개인 결과를 조회할 수 있다. |

#### 9-7. 결과 공개

| 단계 | 관리자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 결과 공개 설정에 진입한다. | 평가 회차의 결과 항목별 공개 상태를 표시한다. |
| 2 | 팀 결과 공개 여부를 설정한다. | 팀 1위 또는 팀 순위 공개 설정을 저장한다. |
| 3 | 개인 결과 공개 여부를 설정한다. | 개인 점수와 개인 순위 공개 설정을 저장한다. |
| 4 | 공개 설정을 저장한다. | 학생 결과 화면에 공개 설정을 반영한다. |

#### 9-8. 시드 반영 및 다음 팀 편성

| 단계 | 관리자 행동 | 시스템 처리/반응 |
|---|---|---|
| 1 | 평가 결과 계산을 완료한다. | 개인별 최종점수를 확정한다. |
| 2 | 시드 반영을 수행한다. | 개인 최종점수를 누적 시드에 반영한다. |
| 3 | 다음 평가 회차를 생성한다. | 새로운 회차 정보를 저장한다. |
| 4 | 자동 팀 편성을 실행한다. | 누적 시드를 기준으로 다음 회차의 팀을 구성한다. |
| 5 | 편성 결과를 검토하고 수정한다. | 관리자가 최종 팀 구성을 조정할 수 있도록 한다. |

**완료 조건:** 관리자가 `평가 회차 생성 → 팀 편성 → 평가 설정 → 평가 진행 → 결과 계산 → 공개 → 시드 반영 → 다음 팀 편성`의 전체 운영 흐름을 관리할 수 있다.

## 역할별 전체 사용 흐름

### 수강생

`로그인 → 학생 홈 → 팀/과제 확인 → 팀 평가 → 개인 평가 → 제출 현황 확인 → 공개 결과 확인`

### 튜터/관리자

`수강생 관리 → 평가 회차/과제 생성 → 팀 수 설정 → 팀 편성 → 평가 템플릿 작성 → 평가 시작 → 평가 종료 → 점수/순위 계산 → 결과 공개 설정 → 시드 반영 → 다음 회차 팀 편성`
